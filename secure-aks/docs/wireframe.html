04

Controls mapped to AKS best practices

Identity without secrets

User-assigned managed identity for the control plane; Workload Identity + OIDC for pods.

identity{} · oidc_issuer_enabled · workload_identity_enabled

Entra ID + Azure RBAC

Cluster access via Entra groups only; local Kubernetes accounts disabled.

azure_rbac_enabled · local_account_disabled = true

Private control plane

API server has no public endpoint; reach it via jumpbox or az aks command invoke.

private_cluster_enabled = true

Network policy dataplane

Azure CNI Overlay with the Cilium dataplane, ready for default-deny policies.

network_plugin_mode = overlay · network_policy = cilium

Private registry & secrets

ACR & Key Vault public access off, private endpoints, RBAC pulls & reads.

public_network_access_enabled = false · AcrPull

Governance & threat detection

Azure Policy (Gatekeeper) guardrails and Microsoft Defender for Containers.

azure_policy_enabled · microsoft_defender{}

Node hardening

Azure Linux OS, encryption-at-host, zonal spread, system/user pool isolation.

os_sku = AzureLinux · host_encryption_enabled

Patching & hygiene

Auto-upgrade (stable) + node-image upgrades in maintenance windows; Image Cleaner.

automatic_upgrade_channel · image_cleaner_enabled

△ Hardening beyond this POC

  • Controlled egress: Azure Firewall + User-Defined Routing (or NAT Gateway) instead of load-balancer egress.
  • Hub VNet with Bastion / jumpbox for private API access; default-deny CiliumNetworkPolicy per namespace.
  • Pod Security Admission (restricted) and the pod-security-baseline Azure Policy initiative.
  • Customer-managed keys (CMK) for disks, ACR & Key Vault; Private Link for Log Analytics (AMPLS).
